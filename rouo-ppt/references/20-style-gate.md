# 风格门 · 读完需求必须问

> **这是铁律 6。** 每次读完用户需求、动手之前，必须把风格选择摆到用户面前。
> 不豁免：需求很清晰也问、用户给了品牌名也问、用户说"随便"也问（那就给推荐并等确认）。

---

## 一 · 为什么必须先问风格

风格不是"好不好看"的偏好，它决定**后面每一步的技术选择**：

| 风格一定 | 立刻被锁定 |
|---|---|
| 字体族 | 衬线 / 无衬线 / 等宽的分工表 |
| 色彩系统 | 从哪几套预设里选、允不允许自定义 |
| 布局骨架 | 用哪套版式库（10 式 / 22 式 / 自由） |
| 背景层 | 要不要 WebGL、要不要纸纹、要不要网格 |
| 交付路径 | 网页 deck 还是原生 PPTX、能不能走 COM 量产 |
| 反平庸的禁区 | 每种风格有自己的红线（极简风禁渐变，电子风禁无脑圆角卡片） |

**风格定错，等于整个 deck 要从头再来。** 所以这一步不能猜、不能默认、不能"先做一版看看"。

### 与方向门的先后关系

```
读需求 → 事实核验（铁律 1）→ 【风格门】铁律 6 → 方向门（铁律 2，三版实视觉）→ 动手
```

**风格门定"哪一种美学体系"**（字体、色系、骨架、能力边界），**方向门定"这个体系里的哪一种诠释"**。

- 风格门：四五个选项，是**体系级**选择 → 用户选 1 个
- 方向门：三版真实视觉，是**诠释级**选择 → 用户选 1 个

不要合并。也不要用方向门的三版去代替风格门——三版同属一个体系时，用户在选"同一个东西的三种做法"，而不是"我想要哪种东西"。

已选定风格后的迭代、加页、换素材：**不重复问风格门**，直接沿用 `direction-choice.md` 里记录的风格。

## 二 · 五个风格族

| # | 风格族 | 一句话 | 美学锚点 |
|---|---|---|---|
| 1 | **电子风** `electronic` | 电子杂志 × 电子墨水 | *Monocle* 杂志贴上了代码 |
| 2 | **极简风** `minimal` | 瑞士国际主义 | Massimo Vignelli + Helvetica Forever |
| 3 | **水彩风** `watercolor` | 纸上的颜料在晕开 | 手稿本、植物图鉴、建筑水彩 |
| 4 | **编辑风** `editorial` | 纯黑白墨的书籍排印 | 旧版《国家地理》+ 企鹅书封 |
| 5 | **蓝图风** `blueprint` | 工程制图的理性浪漫 | 建筑蓝图 + 电路原理图 |

三选一主打（电子风 / 极简风 / 水彩风），两个备选（编辑风 / 蓝图风）。详细规格分别在 `21` / `22` / `23` / `24`。

### 快速识别表

| 用户或内容长这样 | 推荐 |
|---|---|
| 人文分享、行业观察、商业发布、要"杂志感" | **电子风** |
| 不确定选啥、想要最安全的体面 | **电子风**（墨水经典主题） |
| AI / 科技 / 工程 / 数据密集、要信息图感 | **极简风** |
| 大量 KPI 数字 / 路线图 / 流程 / benchmark | **极简风**（Data Hero 是它的专长） |
| 有大量纪实照片、人文图片 | **电子风**（图片网格是它的专长） |
| 文学、植物、旅行、心理、手作、生活方式、儿童 | **水彩风** |
| 想要"温柔但有品味"、拒绝冷硬科技感 | **水彩风** |
| 书评、历史、文化长文、印刷物质感 | **编辑风** |
| 产品规格、架构、系统关系、教学拆解 | **蓝图风** |

## 三 · 询问方式（照这个结构问）

一次问清，不要挤牙膏。三个问题打包：

```
1. 风格：五族选一（电子风 / 极简风 / 水彩风 / 编辑风 / 蓝图风）
        → 附一句"看你内容是 XX，我建议 YY，理由是 ZZ"
2. 主题色：该风格下的预设色板选一套（不允许自定义 hex）
3. 交付：网页 deck（横滑翻页+演讲者模式）还是原生可编辑 PPTX
```

第 3 问是新增的硬问题。两个交付物能力不同：

| | 网页 deck | 原生 PPTX |
|---|---|---|
| 翻页 | 横滑 / 键盘 / 滚轮 / 触屏 | PowerPoint 原生 |
| 动态背景 | WebGL 实时流体 / 网格 | 静态底图 |
| 演讲者模式 | 内嵌，含观众屏同步、计时、排练、激光笔 | 依赖 PowerPoint 自身 |
| 可编辑性 | 改 HTML 源码 | **双击就能改字改图** |
| 交接给他人 | 发一个 HTML 文件即可 | 标准 office 格式 |

**默认建议**：现场演讲、要视觉冲击、自己讲 → 网页 deck；要交给别人改、要走审批流程、要做存档 → 原生 PPTX。

风格与交付格式的可行组合见每份风格文档的"能力边界"一节，**水彩风不支持 COM 量产线**，这个限制必须提前告知。

## 四 · 问完必须落档

风格一经确认，写进项目目录的 `direction-choice.md`，格式：

```markdown
## 风格门（铁律 6）
- 风格族：极简风 minimal
- 主题色：🔵 克莱因蓝 IKB
- 交付格式：网页 deck（单文件 HTML）
- 用户原话：「要数据感强一点，能用键盘翻页」
- 确认时间：2026-09-14
```

**这份记录是后续迭代的唯一依据。** 加页、改稿、补素材时先读它，不许临场换风格——一份 deck 全程只用一套体系、一套主题色，中途换色是最彻底的翻车方式。

### 豁免的三种情况（全部要落档原话）

1. 用户**本次会话明说**跳过（「不用问，直接做」）→ 落档后按内容推荐一个，并明说"按 X 风做的，要换现在说"
2. **已选定风格的迭代**（读 `direction-choice.md` 已有的风格记录）
3. **非设计的机械操作**（转格式、导出、截图、修 bug、纯文字改动）

---

## 五 · 组合禁忌

风格族之间**不能混搭**，这是硬规则：

- ❌ 极简风的网格骨架 + 电子风的衬线大标题 → 两个体系打架
- ❌ 水彩风的晕染背景 + 极简风的直角纯色卡 → 质感和骨架互相拆台
- ❌ 同一份 deck 里两种风格的前后页 → 观众会以为拼错了文件

一条 deck 从封面到尾声只属于一个风格族。**要换风格，是新做一份，不是改几页。**
