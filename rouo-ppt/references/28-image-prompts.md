# 配图提示词库 · 图像生成与素材标准化

> 什么时候读：页面需要**生成的图**（不是找来的真实 logo、不是用户给的截图）。
> 一句话原则：**配图是嵌进页面的素材，不是一张独立幻灯片。** 提示词只管定基调、比例和密度，
> 不要写成散文，更不要让模型在画面里画页眉页脚。
>
> 真实 logo 走 `05-brand-assets.md`；用户截图走 `26-shot-framing.md`；本文件只管「生成什么图、什么比例、什么基调」。

---

## 一 · 十条通用规则（先过这里，再挑类型）

1. **先定基调再写提示词**：基调由**风格族**决定（见 §四），不是每张图临时拍脑袋。
2. **文字语言跟随 deck 语言**：中文 deck 的图内文字用中文，英文 deck 用英文，**不混排**。
3. **不生成**：卡通、3D 渲染、霓虹科技感、SaaS 模板感、过度装饰、伪造 logo、水印。
4. **留出叠加空间**：图片要能给标题或正文留白，不要满屏堆细节。
5. **同组同规格**：同一页或同一组图片必须**同比例、同视觉缩放、同边距密度**。
6. **不画 slide chrome**：不要页眉、页脚、页码、标题栏、角标、署名、装饰边框——这些是页面的活，不是图片的活。
7. **主体留安全区**：主体居中但保留边距；超宽图（21:9）主体必须落在**中央 70% 安全区**。
8. **一次只生一张**：多图页逐张生成，每张都补一句「这是一组图片中的一张」（见 §三 C）。
9. **落盘命名**：`images/{页号}-{语义}.{ext}`，例：`images/p04-pipeline.png`。
10. **生成后必检**：比例是否为目标槽位、密度是否与同组一致、有没有多出文字或边框。

---

## 二 · 比例选择（先选槽位，再生图）

**不要先生成图片再硬塞进页面。** 先决定图片落位，再按落位比例生成。

| 用途 | 推荐比例 | 典型落位 |
|---|---|---|
| 章节封面 / 全屏主视觉 | 16:9 | 满屏背景 / hero |
| 顶部横幅 / Image Hero | 16:9 或 21:9 | 页顶通栏通吃 |
| 左文右图主图 | 16:10 或 4:3 | 半屏图框 |
| 信息图 / 系统关系图 | 16:9 或 16:10 | 满宽信息区 |
| 截图再设计 / UI 情景图 | 16:10 或 21:9 | UI 情景框 |
| 图文混排小图 | 3:2 或 3:4 | 侧栏小图 |
| 图片网格 / 面板组 | 统一横图 | 等高等宽格 |
| 竖版载体（小红书 / Story） | 3:4 或 9:16 | 见 `32-canvas-formats.md` |

**三种填充语义**（写进页面时定，不是生图时定）：

- `cover` —— 纪实照片默认。铺满、允许裁切，保留画面张力。
- `fit-contain` —— **不可控的原始素材**（真实截图、含文字的图）默认。宁可留白，**不裁掉关键文字**。
- 重生成铺满 —— GPT 类模型按槽位**重新生成**时，必须生成同槽位比例并铺满，不要让小图漂在白框里。

## 三 · 图片标准化策略

### A. 用户原始图片 / 截图

原始截图比例通常不可控，**不要直接当最终视觉标准**。按顺序处理：

1. 内容需要保真 → 走 `26-shot-framing.md` 的程序化适配（目标比例画布 + 风格化背景 + 等比缩放 + 语义化留白）
2. 比例接近目标槽位 → 直接放进统一图框，用 `cover` 或 `fit-contain`
3. 一张 UI 图被拉成巨长条 → 拆成 2–3 张同尺寸局部面板，**每个面板同一高度类**
4. 过高/过窄/过长且适配解决不了 → 用「截图再设计」类型重新生成到目标比例
5. 必须保原图 → `fit-contain` + 接受留白，不裁关键文字

### B. 提示词后缀（每张都补，别省）

```text
输出必须是[16:9/16:10/4:3/3:2]横向构图，主体居中但保留边距，画面密度中等，
与同组图片保持相同视觉缩放和边距。只保留核心图形/画面本身，
不要生成页眉、页脚、标题、页码、角标、署名、装饰边框、超长条、竖图或不规则比例。
```

同页多图时再补一句：

```text
这是一组图片中的一张，请保持与同组图片相同的画面比例、元素大小、边距、线条粗细和标注密度。
```

## 四 · 五族风格的配图基调（rouo 自有映射）

配图必须和风格族同一个美学体系，**不要用一套图打通五族**。

| 风格族 | 配图基调关键词 | 明确禁止 |
|---|---|---|
| **电子风** | 电子杂志 × 电子墨水；克制、真实、留白充足；黑白灰 + 少量低饱和强调色；细线、网格、编号、短标签 | 满屏细节、霓虹、glow、拟物 |
| **极简风** | 国际主义排印风；12/16 列网格、非对称留白、左对齐、`1px` 发丝线、直角模块；黑/白/灰 + **单一**主题 accent | 渐变、阴影、圆角、玻璃拟态、多色 |
| **水彩风** | 纸与颜料的质感；颜料渗化边缘、纸纹、水痕、留白即水面；色彩低饱和、同类色过渡 | 线性渐变（是电脑味不是颜料味）、死板描边、纯黑 |
| **编辑风** | 黑白纸墨的书籍排印；高对比线稿、网点/半调、粗细分明的标题字、栏线 | 彩色卡片、圆角、阴影、插画感 |
| **蓝图风** | 工程制图；单色线稿 + 网格底、标注引线、尺寸线、图号框、等宽字标注 | 贝塞尔曲线连接、立体渲染、彩色填充块 |

**共同底线**：图片来源可追溯（真实现场 / 真实界面 / 数据），**不用「通用科技动画」那种任何产品都长一样的图**（`06-taste-rules.md`）。

## 五 · 类型库（通用七型）

每型给一个可直接填空的提示词骨架。`[方括号]` 是要替换的槽。

### 类型 1 · 人文纪实照片

用于增加现场感、情绪和真实世界锚点。

```text
生成一张横向纪实摄影配图，主题是：[页面概念]。自然光、低饱和、轻微胶片颗粒、
真实工作或生活现场，克制、有人文温度。[风格族基调]。留出标题空间。
不要商业摆拍、科幻界面、AI 机器人、logo 或水印。[后缀]
```

### 类型 2 · 信息图

用于解释概念、关系、分类。

```text
生成一张横向信息图，解释：[概念/关系]。细线条、网格、编号、短标签、留白充足。
图中文字使用[中文/英文]，保持简短可读。[风格族基调]，单一强调色。
不要卡通、3D、霓虹科技感或模板感。[后缀]
```

### 类型 3 · 流程 / Pipeline 图

用于讲清从 A 到 B 到 C。

```text
生成一张横向流程信息图，展示：[步骤 1] → [步骤 2] → [步骤 3] → [结果]。
细箭头、分段编号、短注释、克制留白。图中文字使用[中文/英文]。[后缀]
```

### 类型 4 · 对比图

用于 before / after、新旧模式、两种方案对照。

```text
生成一张横向对比信息图，左侧是[旧模式]，右侧是[新模式]。
细线分栏、短标签、清晰层级、黑白灰 + 一个低饱和强调色。
图中文字使用[中文/英文]。[后缀]
```

### 类型 5 · 系统关系图

用于多角色 / 多工具 / 多模块之间的关系。

```text
生成一张横向系统关系图，展示：[角色/工具/模块]之间如何连接。
节点、细线、箭头、编号和少量短注释，结构清晰，留白充足。
图中文字使用[中文/英文]。[后缀]
```

### 类型 6 · 截图再设计 / UI 情景图

用于把真实截图、代码、设计稿处理成统一视觉素材。

```text
生成一张横向 UI 情景图，把[截图/界面/工作区内容]再设计成[风格族]的视觉。
保留真实产品工作流的感觉，使用纸张底色、细线框、网格、少量标注。
图中文字使用[中文/英文]，短而清晰。不要真实品牌 logo、花哨 dashboard、霓虹渐变。
输出必须是 16:10 横向构图。[后缀]
```

### 类型 7 · 数据大字报图

用于突出一个关键数字或少量指标。

```text
生成一张横向数据大字报视觉，核心数字是：[数字]，含义是：[含义]。
超大数字、少量短注释、细线、留白。图中文字使用[中文/英文]。
只保留核心数据视觉本身，不要页眉页脚页码角标署名装饰边框。比例：16:9。
```

## 六 · 超宽横幅（21:9）专用规则

顶部横幅是最容易做废的一类——**主体贴边 = 必废**。

- 严格 12/16 列网格、非对称留白、左对齐、直角模块、发丝线
- 色彩只用黑/白/灰 + **一个**主题 accent
- **核心主体必须落在中央 70% 安全区**：人脸、关键节点、UI 文字都不许贴边
- 不要块内文字（横幅上的文字由页面负责，不由图片负责）
- 多图格版本（2–6 张并列）逐张生成，且**每张补「这是一组中的一张」+ 同网格规格**

```text
生成一张 21:9 超宽横向配图，主题是：[页面概念]。
构图有大量负空间，主体位于中央 70% 安全区，四周留白。
[风格族基调]。不要文字、logo、水印。
只保留核心画面本身，不要页眉、页脚、标题、页码、角标、署名、装饰边框。[后缀]
```

## 七 · 背景图提示词

页面需要一张**满屏氛围底**时（不是内容图），走这套。

| 要点 | 说明 |
|---|---|
| 密度 | **极低**。背景要能在上面压文字，任何抢注意力的细节都是错的 |
| 对比 | 与正文文字保持 ≥ 4.5:1（小字）/ ≥ 3.0:1（≥24px 大字）；不够就加蒙层 |
| 中心 | **中心区留空**给内容，纹理/结构推向边缘 |
| 比例 | 与画布同比例（见 `32-canvas-formats.md`），不要 16:9 硬塞进竖版 |
| 可读性兜底 | 生成后必须实测：把正文放上去，用 `29-preflight-checklist.md` 的对比度规则过一遍 |

```text
生成一张满屏氛围背景图，主题是：[`页面氛围`]。整体低对比、低密度、中心区域留空，
结构或纹理推向画面边缘。不要任何文字、logo、水印、页码。
不要出现具体的可识别人物或品牌。[后缀]
```

**水彩风 / 电子风**的背景经常需要「可叠加」而不是「可看清」——这类图宁可比内容图更淡一档。

## 八 · 产出与校验

- 落盘：`images/`，命名 `{页号}-{语义}.{ext}`
- 记录：把每张图的**生成意图 + 落位 + 比例**写进项目 `design-lock.md` 或 `deck_data.json` 的对应元素，避免后续改稿时不知道该重生成哪张
- 校验（生成后逐项过）：
  - [ ] 比例 = 目标槽位，且**同组同规格**
  - [ ] 图内文字语言 = deck 语言，且短
  - [ ] 没有多出页眉/页脚/页码/边框/水印/伪造 logo
  - [ ] 21:9 主体在中央 70% 安全区内
  - [ ] 作为背景时，正文对比度达标（`29-preflight-checklist.md`）
  - [ ] 与风格族基调一致（§四对照表）

> 配图错了要重生成，**不要靠后处理修**——拉伸、加滤镜、贴白块都是把问题推到交付那一刻。
