# 手作线 · 主线工作流（五阶段）

> 手作线是设计驱动的产线：视觉品质至上、每页可各不相同。
> 量产线（数据驱动）见 `10-drive-engine.md`。快道见 `02-express.md`。

---

## 总览

```
阶段 A · 定向     澄清 → 事实验证 → 资产协议 → 方向门 → ⛔用户选定
                                                              ↓
阶段 B · 立约     沟通契约 → 设计简报（页面队列）→ 设计锁 → ⛔用户确认
                                                              ↓
阶段 C · 备图     取齐内容必需的图（三方向与执笔共用同一批）
                                                              ↓
阶段 D · 执笔     逐页手写 SVG（P01…PN）+ 早期门 + 终门
                                                              ↓
阶段 E · 交付     后处理 → 导出原生 PPTX → 可选 PDF / 视频
```

**两个 ⛔ BLOCKING 门**：A 末（方向选定）、B 中（简报确认）。到门**停轮等用户明确回应**，不得代替用户决策。门之后的非阻塞步骤连续跑完，不需要用户每次说「继续」。

---

## 阶段 A · 定向

### A1 · 澄清需求

用**对话**了解（一次最多 3 个问题）：目标受众 / 核心信息 / 情感基调 / 输出格式。

**同时主动索要参考材料**——最容易被跳过、却最该问的一步，一次问全：

- 这个项目/产品**叫什么名字**？
- 有没有 **logo、品牌色、VI、字体规范**？有就发我。
- 有没有**你喜欢的参考**——某个网站 URL、一张截图、某个产品「就要那种感觉」？
- 都没有也没关系，说一句「你看着办」，我直接做几版给你挑。

⏱️ **无应答策略**：问题发出后用户没回应任何信息 → 不要枯等。按 best judgment 补齐假设（标 assumption），直接跑完 A2–A4，把三版真实视觉摆出来——**用「看得见的东西」代替继续追问**。

### A2 · 事实核验（铁律 1）

任务涉及具体产品/机构/技术/事件时，**这是第一个动作**，做在澄清提问之前。结果写进 `facts.md`。

### A3 · 资产协议（铁律 4）

用户给了能去官方渠道找到 logo 的品牌/机构名 → 走 `05-brand-assets.md` 取齐资产，产 `brand-kit.md`。

⚠️ **普通主题名不算品牌名**：「咖啡 / 鹦鹉 / 历史 / 健身」是**内容主题**，不要跑去找「咖啡的 logo」空转。

### A4 · 固定设计简报的输入（三方向的唯一共同输入）

把 A1–A3 澄清到的东西整理成一份 **≥500 字的设计输入**——这是三个方向的唯一共同输入，写薄了三版都会飘。必须覆盖：

1. 项目**是什么**（商业提案？课程汇报？机构介绍？定性）
2. **目标受众与使用场景**（含**观看距离**——10cm 手机 / 1m 笔记本 / 10m 投屏，决定字号）
3. **核心信息与内容板块**（分点列出，直接对应到页）
4. **情感基调与气质关键词**
5. **输出格式与尺寸（必填）**——三版统一，否则无法横向对比
6. **已知约束**（品牌色 / 禁忌 / 必含元素）
7. **图片需求判断**（内容必需 vs 装饰；拿不准按内容必需处理）
8. **视觉母题假设**——这个内容**独有的**视觉元素/结构/隐喻

**视觉母题怎么找**：从内容里找一个别的主题不会有的视觉元素/结构/隐喻，作为形式的种子。判断标准：**母题是「设计从内容长出来」的最小证据**，答不出说明还在靠风格标签抽签。每版交付时要写一句「形式来自内容的哪里」，写不出来 = 在套模板，回去重答。

### A5 · 方向门（铁律 2）

详细流程 → `03-direction-gate.md`。核心：三套互补逻辑各产出一版真实视觉，展示后**停轮**等用户选。

### A6 · 记录用户选择

用户选定后**立刻**把「展示了哪几版、截图路径、用户选择原话」写进 `direction-choice.md`。这是 Gate 文件，开工前必须存在。

## 阶段 B · 立约

### B1 · 项目初始化

```
<project>/
├── content.md              # 内容底稿（真实数据，禁止改写编造，标注来源）
├── facts.md                # 事实核验记录（如触发）
├── brand-kit.md            # 品牌资产包（如触发）
├── direction-choice.md     # 方向门记录 + 用户选择原话
├── design-brief.md         # 设计简报（含页面队列）
├── design-lock.md          # 设计锁（执笔必读）
├── sources/                # 原始素材与转换产物
├── assets/img/             # 取到的图与 logo
├── svg_output/             # 逐页 SVG
└── exports/                # 最终交付
```

### B2 · 立约产出

**硬规则 —— 页面规划只从「用户请求 + 内容事实 + 对话约束」推导**，不从任何模板库反推。

要产出四样东西：

1. **沟通契约**——这份 deck 怎么说服人（第 1 页到最后一页的论证结构）
2. **设计简报** → `design-brief.md`（模板见 `07-brief-and-lock.md`）
3. **页面队列**——简报里必须有一节**有序页面清单**：一条 = 一页最终幻灯片，含 id、页面角色、核心信息、`rhythm`（`anchor` 立论 / `dense` 密集 / `breathing` 呼吸）、版式继承、图表引用
4. **设计锁** → `design-lock.md`（模板见 `07-brief-and-lock.md`）

### ⛔ BLOCKING · 简报确认

把沟通契约 + 页面队列摆给用户，**停轮等明确确认**。

⚠️ **不得跨阶段捆绑**：确认之前不能产出设计锁之后的东西，不能预写 SVG。「提前准备」是禁止的。

### B3 · 页面队列是硬约束

队列 id 与顺序在绘制过程中**永不增删、合并、拆分、重排**。确需调整：先修清单块，再继续；超出用户确认的页数范围要重新确认。

## 阶段 C · 备图

**素材齐了再设计，不是边设计边占位。**

| 内容类型 | 首选来源 |
|---|---|
| 博物 / 历史 / 艺术 / 动植物 / 古典 | 公共领域图库、美术馆开放藏品 |
| 通用生活 / 场景 / 产品摄影 | Unsplash、Pexels（免版权） |
| 用户自己的产品 / 品牌 | 走资产协议取官方图 |
| 设计里要**点名 / 并列展示**的品牌产品 | 走资产协议取每个的官方 logo |

**真图诚实性测试**：「去掉这张图，信息是否有损？」有损才用。别配 stock「灵感图」——那是平庸产物。

❌ 内容必需的图**绝不用色块 / SVG 几何糊弄**——做产品 deck 没有产品图 = 失败。

**取图失败三级兜底（不许卡死）**：换源 → 参考图生成（需用户确认有生图能力）→ 标注「图待补」诚实占位继续往下，交付时一句话告知。**取图失败是降级继续，不是 STOP。**

**内嵌策略**：交付形态是双击就能开的单文件 HTML 时，logo/图片**必须 base64 内嵌**——相对路径挪个目录就全员裂图。

## 阶段 D · 执笔

🚧 **GATE**：B、C 完成；`design-brief.md` + `design-lock.md` 存在。

### D0 · 动笔前必做

1. 批量读核心参考：`08-page-craft.md`、`09-shape-language.md`
2. **设计参数确认**（第一页 SVG 之前输出）：沟通目标、画布尺寸、正文字号、配色 HEX、字体方案、逐角色校准表
3. **实时预览**（建议）：第一页之前启动，旁路进程不等它

### D1 · 逐页手写 SVG（核心）

写进 `<project>/svg_output/`，文件名零填充（`01_cover.svg` … `12_end.svg`）。三条硬约束：

1. **SVG 必须手写，禁止脚本生成。** 写脚本循环产出页面是禁止的——即使以「省 token」「用户着急」为由。跨页一致性依赖带着完整上游上下文逐页作者化。
2. **顺序生成，禁止分批。** 一页一页连续生成，按「先做 5 页」分组是禁止的。
3. **严禁子代理生成 SVG。** 页面必须由当前主 agent 端到端完成。

**每页动笔前重读 `design-lock.md`**——所有色彩/字体/图标/图片从锁里取，不得凭记忆或临场发明。空/缺失的条目是立约时的**刻意信号**，不是遗漏。

**长 deck 锁重读**：P05、P10、P15… 之后若还有下一页，下一页前完整重读一次锁——纯重锚定，不跑质检不停顿。

### D2 · 门点质检（节奏强制）

```
P01–P05 → 早期门 → 剩余页 → 终门     （计划页数 ≤6 时跳过早期门）
```

质检只由两种事件触发：**覆盖页均已存在的门点**，或**一次整合修复的结束**。在这两个事件之外跑质检 = 节奏违规。

### D3 · 修复纪律

**在拥有故障的最浅层修复**：页面局部问题修那一页；清单/规格/资源问题修立约产物；工具失败修源头产物。**不要静默降级必需产物。**

## 阶段 E · 交付

### E1 · 后处理 + 导出

```bash
# 终检（阻塞错误全修，一次整合修复，再一次验证重跑）
python "…/rouo-ppt/scripts/tools.py" check <project> --quick-generate --canonical-authoring --stage final --json

# 导出原生 PPTX
python "…/rouo-ppt/scripts/tools.py" export <project> --quick-generate --with-notes
```

> 工具调度器的实际部署路径见 `19-environment.md`。导出的形状是原生 DrawingML，PowerPoint 双击可改字。

需要 PowerPoint 原生 Chart/Table 对象（能「编辑数据」）→ 加 `--native-charts-and-tables`，单独存 `*_native_charts_tables.pptx`。

### E2 · 可选交付

PDF / 备注 / 旁白 / 动画 / 视频 / 评审 → 对应参考文档。

### E3 · 验收自检

- [ ] `direction-choice.md` 存在且记录了用户选择原话
- [ ] 页面队列页数与实际 SVG 数一致，id 与顺序对得上
- [ ] 交付文件能在 PowerPoint 打开，文字可双击编辑
- [ ] 肉眼过一遍——**AI 写的代码经常有交互 bug**
- [ ] 已知降级（缺 logo / 缺图）已向用户明说
