# 品牌资产协议 + brand-kit 模板

> 铁律 4 的完整执行。**触发**：① 为某个品牌/机构做物料；② 设计里要**呈现**一个或多个真实可识别的产品/品牌——对比 / 榜单 / 评测 / 介绍 deck（第二类最常被漏）。
> ⚠️ **走方向门也不豁免取 logo**——方向门决定视觉风格，取 logo 是并行的另一件事。

---

## 核心理念：资产 > 规范

**品牌的本质是「它被认出来」。** 按识别度排序：

| 资产类型 | 识别度贡献 | 必需性 |
|---|---|---|
| **Logo** | 最高 · 出现就一眼识别 | **任何品牌都必须有** |
| **产品图 / 渲染图** | 极高 · 实体产品的主角 | **实体产品必须有** |
| **UI 截图 / 界面素材** | 极高 · 数字产品的主角 | **数字产品必须有** |
| 色值 | 中 · 脱离前三项时经常撞衫 | 辅助 |
| 字体 | 低 | 辅助 |

**翻译成执行规则**：
- 只抽色值 + 字体、不找 logo/产品图/UI → **违反协议**
- 用剪影/手画 SVG 替代真实产品图 → **违反协议**
- 找不到资产不告诉用户、硬做 → **违反协议**
- **宁可停下问用户要素材，也不用通用填充**

## 五步硬流程（每步有兜底，绝不静默跳过）

### Step 1 · 问（资产清单一次问全）

```
关于 <brand/product>，你手上有以下哪些资料？我按优先级列：
1. Logo（SVG / 高清 PNG）—— 任何品牌必备
2. 产品图 / 官方渲染图 —— 实体产品必备
3. UI 截图 / 界面素材 —— 数字产品必备
4. 色值清单（HEX / RGB / 品牌色盘）
5. 字体清单（Display / Body）
6. 品牌规范 PDF / Figma / 官网链接

有的直接发我，没有的我去搜/抓。
```

### Step 2 · 搜官方渠道

| 资产 | 搜索路径 |
|---|---|
| **Logo** | 官网 `/brand` · `/press` · `/press-kit` · 官网 header 的 inline SVG |
| **产品图** | 官网产品页 hero + gallery · 官方新闻稿附图 · 发布视频截帧 |
| **UI 截图** | App Store / 应用商店产品页截图 · 官网 screenshots 区 |
| **色值** | 官网 inline CSS / 品牌规范 PDF |
| **字体** | 官网 stylesheet · 品牌规范 |

`WebSearch` 兜底关键词：`<brand> logo download SVG`、`<brand> press kit`。

### Step 3 · 下载（按本机可达性裁剪，见 `19-environment.md`）

**Logo 按成功率递减**：

```bash
# 0. 图标聚合源（数字产品/SaaS 首选，本机已验证可达）
curl -o logo.svg "https://cdn.simpleicons.org/<slug>/<hexcolor>"

# 1. 官方独立 SVG/PNG / brand 页
curl -A "Mozilla/5.0" -L -o assets/<brand>/logo.svg "<official-url>"

# 2. 官网 HTML 提取 inline SVG（下载首页后 grep <svg> 节点）
```

❌ **本机死路，不要尝试**：Google favicon 服务、Wikimedia、Clearbit。

下载后**逐个核对**（本机有假 200 陷阱）：
```bash
file <logo>            # 真 SVG/PNG，不是 HTML 空壳
head -c 90 <logo>.svg  # 应以 <svg 开头
wc -c <logo>           # 明显偏小（~106字节）即丢弃
```

**产品图**：官方产品页 hero（常 2000px+）→ press kit → 发布视频截帧 → AI 生成兜底（以官方参考图为基底）。

**UI 截图**：应用商店产品截图（注意可能是 mockup）→ 官网截图区 → 官方演示视频截帧。

### Step 4 · 验证（不只是 grep 色值）

| 资产 | 验证动作 |
|---|---|
| Logo | 文件存在 + 可打开 + 至少深浅两版 + 透明背景 |
| 产品图 | 至少一张 2000px+ 干净背景 |
| UI 截图 | 分辨率真实 + 最新版本 |
| 色值 | `grep -hoE '#[0-9A-Fa-f]{6}' assets/<brand>/*.{svg,html,css} \| sort \| uniq -c \| sort -rn \| head -20`，过滤黑白灰 |

⚠️ **警惕示范污染**：产品截图里常有用户 demo 的品牌色，那不是该工具的色。
⚠️ **品牌多切面**：官网营销色与产品 UI 色经常不同——两套都是真的，按交付场景选。

### 素材质量门槛「5-10-2-8」（铁律）

> **Logo 例外**：有就必须用，不适用此门槛。**其他素材**走质量门槛：

| 维度 | 标准 |
|---|---|
| **5 轮搜索** | 多渠道交叉搜，不拿第一页结果直接用 |
| **10 个候选** | 至少凑 10 个备选才开始筛 |
| **选 2 个好的** | 从 10 个里精选 2 个 |
| **每个 ≥8/10 分** | 不够 8 分**宁可不用**（诚实占位或 AI 生成） |

**8/10 评分维度**：① 分辨率 ≥2000px ② 版权清晰（疑似盗图 0 分）③ 与气质关键词契合 ④ 光线/构图/风格一致 ⑤ 独立叙事能力。

**宁缺毋滥**——7 分素材 = 扣分项，不如留空。

## 🛑 自检门（进方向门前必过）

把设计里会出现的品牌名逐个列清单，确认**每个都取到官方 logo**。**清单里有一个没取到 = STOP 补齐。** 实在全网取不到 → **诚实降级**：字体 wordmark + 品牌色 + 角标注明「官方 logo 待补」，**绝不伪造图形 logo**。

---

## 失败兜底

| 缺失 | 处理 |
|---|---|
| **Logo 完全找不到** | **停下问用户**，不要硬做 |
| 产品图找不到 | AI 生成（以官方参考为基底）→ 向用户索取 → 最后才诚实占位（灰块+文字标签+「待补」角标） |
| 色值找不到 | 走方向门，向用户推荐 3 个方向并标注 assumption |

**禁止**：找不到就静默用剪影/通用渐变硬做——这是本协议最大的反模式。

**代价账**：正确走完协议 ≈ 30 分钟；不做的代价 = 没识别度的通用产出 → 用户返工 1–2 小时甚至重做。**这是稳定性最便宜的投资。**

## `brand-kit.md` 模板（走完协议后固化）

```markdown
# <Brand> · 品牌资产包

> 采集日期：YYYY-MM-DD
> 资产来源：<下载来源 URL>
> 资产完整度：<完整 / 部分 / 推断>
> 本机可达性备注：<因网络降级的项写在这里>

## 一 · 核心资产（一等公民）

### Logo（任何品牌必需）
- 主版本（深底用）：`assets/<brand>/logo.svg`
- 反色版（浅底用）：`assets/<brand>/logo-white.svg`
- 取图来源：<simpleicons / 官网 inline SVG / 官方 brand 页>
- 使用场景：<片头 / 片尾 / 角落水印 / 全局>
- 禁用变形：<不能拉伸 / 改色 / 加描边>

### 产品图（实体产品必填）
- 主视角：`assets/<brand>/product-hero.png`（<宽×高>）
- 细节图 / 场景图：…

### UI 截图（数字产品必填）
- 主页：`assets/<brand>/ui-home.png`
- 核心功能：`assets/<brand>/ui-feature-<name>.png`

## 二 · 辅助资产

### 色板（每条标注来源）
- Primary: #XXXXXX   <来源>
- Background: #XXXXXX
- Ink: #XXXXXX
- Accent: #XXXXXX
- 禁用色：<品牌明确不用的色系>

### 字型
- Display: <font stack>
- Body: <font stack>
- Mono（数值/编号/微标签）: <font stack>

### 签名细节 / 禁区 / 气质关键词（3-5 个形容词）

## 三 · 素材评分（5-10-2-8）

| 素材 | 分辨率 | 版权 | 气质契合 | 一致性 | 叙事力 | 总分 |
|---|---|---|---|---|---|---|
| <文件名> | | | | | | /10 |
```

**填写规则**：
1. Logo 有就必须用（出现几个产品取几个 logo）
2. 色值不许凭空发明——写不出「为什么是这个色」= 在抄配方
3. 想临时加色要先改本文件——一致性从「靠自觉」变成「靠结构」
4. 降级必须显式记录，交付时告知用户
