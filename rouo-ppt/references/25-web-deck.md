# 网页 deck · 运行时与交付

> 单文件 HTML 的横向翻页演示。**五族风格都能用它**，其中电子风与极简风的骨架已内建完整运行时。
> 骨架：`assets/deck-shell-electronic.html`（电子风）· `assets/deck-shell-minimal.html`（极简风）

---

## 一 · 什么时候用网页 deck

| 用网页 deck | 用原生 PPTX |
|---|---|
| 现场演讲、要视觉冲击、**自己讲** | 要交给别人改、走审批、做存档 |
| 需要动态背景（WebGL 流体 / 网格） | 需要 PowerPoint 原生图表对象（能"编辑数据"） |
| 需要观众屏同步、计时、排练、激光笔 | 需要打印分发 |
| 一个 HTML 文件就能发出去 | 环境里没浏览器 / 不允许开浏览器 |

**两个都要**时：先做网页 deck 定视觉，再把版式翻译成 SVG→PPTX 出可编辑版本（见 `08-page-craft.md`）。同一页不混用两套视觉规范。

### 2.1 拷完第一件事：改占位符

骨架里有 `[必填]` 占位符。**漏改的话浏览器标签页会显示"[必填] 替换为 PPT 标题"**。

```bash
grep -n "\[必填\]" index.html    # 必须返回空
```

主要改 `<title>`。骨架里 `标签页标题 · Deck Title` 的格式照抄。

### 2.2 再改主题色

打开 `index.html` 的 `<style>`，找 `:root{` 里标着"主题色"的注释块，**整体替换**：

- 电子风：`--ink` `--ink-rgb` `--paper` `--paper-rgb` `--paper-tint` `--ink-tint`（六行）
- 极简风：`--paper` `--paper-rgb` `--ink` `--ink-rgb` `--grey-1/2/3` `--accent` `--accent-rgb` `--accent-on` `--accent-bright`（十个）

其他地方全走 `var(--...)`，**不用逐处改**。色值从 `21-style-electronic.md` / `22-style-minimal.md` 抄，不要临场发明。

## 三 · 翻页与总览

| 操作 | 行为 |
|---|---|
| `←` `→` / `PageUp` `PageDown` / `Home` `End` | 上一页 / 下一页 / 首页 / 尾页 |
| 滚轮 | 翻页 |
| 触屏滑动 | 翻页 |
| `ESC` | 宫格总览（缩略图选页） |
| `P` | 演讲者模式 |

横向排布：`.slide{width:100vw;height:100vh;flex:0 0 100vw}`，容器横向位移翻页。**不要改成纵向滚动**，那会破坏 16:9 固定画布假设。

**每页必须带主题类**（详见对应风格文档）：`slide light` / `slide dark` / `slide light hero` / `slide dark hero`。只写 `hero` 不行。

生成后自检节奏：

```bash
grep -o 'class="slide[^"]*"' index.html | sort | uniq -c
```

## 四 · 图片约定（动手前跟用户讲清）

| 项 | 约定 |
|---|---|
| 位置 | 与 `index.html` 同级的 `images/` |
| 命名 | `{页号}-{语义}.{ext}` → `01-cover.jpg` `03-figma.jpg` `05-dashboard.png`（页号补零，语义用英文短词） |
| 规格 | 单张 **≥ 1600px 宽**（避免大屏模糊）；照片/截图用 JPG，透明 UI/图表用 PNG |
| 体积 | 全部图片**总大小 ≤ 10MB**（影响翻页流畅度） |
| 替换 | **同名覆盖最稳**（HTML 里不用改路径）；改名了要全局搜 `images/旧名` 替换 |
| 没图时 | 先用占位符（电子风 `.img-slot` / 极简风 `data-image-slot`）生成结构，**后期补图**；但要告知：图文混排页没图时无法验证视觉效果 |

**处理用户原始截图** → 走 `26-shot-framing.md`，优先程序化适配，**不要重画**。

## 五 · 演讲者模式与备注（正式演讲必做）

按 `P` 进入。当前窗口变演讲者视图，同时打开独立观众屏。

### 5.1 稳定页面 ID（备注持久化的地基）

```html
<section class="slide light" data-slide-id="codepilot-capabilities" data-theme="light">
```

- 用小写英文 slug：`cover` / `codepilot-capabilities` / `demo-workflow` / `closing`
- **不要用页码当 ID** —— 备注按 ID 存 `localStorage`，用页码会在重排后串页
- 页面重排保留原 ID；只有语义彻底改变才换

### 5.2 先做页面计划表（写 HTML 之前）

| 页码 | `data-slide-id` | 章节 | 页面目的 | 观众屏可见信息 | 演讲者补充 | 建议时长 | 转场 | 可选现场信息 |
|---|---|---|---|---|---|---|---|---|

- **观众屏可见信息**：观众此刻必须读到的结论、证据、结构、图像
- **演讲者补充**：背景、例子、判断依据、语气 —— **不要逐字复述页面**
- **转场**：解释下一页**为什么**紧接着出现，不要只写"下一页"
- **默认做提词卡，不是逐字稿**；只有用户明确要逐字稿才展开

### 5.3 `SPEAKER_NOTES` 结构

顺序必须与 slide 完全一致：

```js
const SPEAKER_NOTES = [
  {
    id: 'codepilot-capabilities',      // 必填：与 data-slide-id 一致
    title: 'CodePilot 能做什么',        // 必填
    section: 'CodePilot',              // 可选：章节名
    minutes: 0.9,                      // 可选：本页建议分钟
    purpose: '先建立完整产品认知，再进入实现过程',   // 必填：这页在叙事中的任务
    talk: [                            // 必填：3–5 条，每条只表达一个意思
      '从用户动作讲能力，不先讲底层实现',
      '用四张截图建立产品全貌',
      '强调模型、工具、上下文在同一工作流里协作'
    ],
    transition: '观众知道产品长什么样后，再回答为什么要这样实现',  // 必填
    cue: '按截图顺序指向四个能力区',      // 可选
    advance: '讲完"同一工作流"后翻页'    // 可选
  }
];
window.__SPEAKER_NOTES__ = SPEAKER_NOTES;
```

| 字段 | 用途 | 界面缺失时 |
|---|---|---|
| `section` | 章节名与进度 | 隐藏章节行 |
| `minutes` | 本页讲述分钟 | 显示 `—` |
| `cue` / `interaction` / `delivery` / `advance` / `fallback` / `pronunciation` | 舞台动作 / 互动 / 语气 / 翻页时机 / 备用方案 / 读音 | 隐藏 |
| `autoAdvanceSeconds` | 本页自动停留秒数 | 用全局间隔或不自动翻页 |

**没有来源支持的事实不能写进备注。** 影响内容正确性的缺失信息标"待补充"或问用户；不影响内容的可选现场信息**直接省略**（不要写占位符进去）。

**`minutes` 是讲述计划，`autoAdvanceSeconds` 是播放行为，两者必须分开。** 不得因为一页建议讲 1 分钟就默认 60 秒自动翻页。

**总建议时长 ≤ 用户时长的 90%** —— 给停顿、互动和现场意外留缓冲。

### 5.4 演讲者界面要点

- **主体两栏**：左预览、右备注；左侧当前页在上、下一页在下
- **两个 iframe 严格 16:9**，空间不足时留边等比缩小，**不得裁切、压扁或让页面内部文字重排**
- 预览 iframe **只在初次挂载时加载 HTML**，翻页用 `postMessage` 发页码，**不要反复改 `src` 重载整份演示稿**
- **底栏三段**：左 = `已进行 / 本页 / 剩余或超时` 三组时间；中 = 两行控制（第一行 `首页/上一页/下一页/尾页`，第二行 `开始计时或暂停 / 重置计时 / 排练`）；右 = `第几页/总页数` + 完成百分比
- 计时按钮必须明确写成 **"开始计时 / 继续计时 / 重置计时"**，别让用户误以为重置整场
- **自动翻页放右上角状态栏**，不占底部翻页区
- **宫格放"当前页"标题旁**，打开后**直接用宫格替换预览区**，不弹突兀的全屏层；`ESC` 切换
- **备注按 `data-slide-id` 存 `localStorage`** 并显示保存状态；切页后滚动回顶部；可调字号
- 光标在备注编辑器里时**不得触发翻页**

### 5.5 观众屏同步状态

同时用 **`postMessage` + `BroadcastChannel` + `storage`** 三条通道同步。演讲者端显示六种状态：

| 状态 | 含义 |
|---|---|
| 连接中 | 观众窗口已开，尚未收到确认 |
| **已同步** | 观众页确认页码与演讲者一致，心跳有效 |
| 未同步 | 心跳有效但两端页码/序列号不同 |
| **已冻结** | 故意保留原页，**不是故障** |
| 未连接 | 未打开 / 已关闭 / 心跳超时 |
| 弹窗被拦截 | 浏览器阻止打开观众窗口 |

**即使某些内置浏览器的 `window.closed` 代理不可靠，心跳超时后也必须落到"未连接"。**

"重新打开观众屏"必须始终可用，恢复后立即发当前页。
退出演讲模式时发送 `bye`；脚本打开的观众窗尝试自动关闭，不允许自关时保留深色"演示已结束"遮罩 —— **不得继续停在最后一页假装演示仍在进行**。

> 浏览器只能确认观众**页面/窗口**的软件同步状态，**不能检测 HDMI / 转接器 / 投影仪线缆是否物理断开**。现场仍应目视确认外接屏。

### 5.6 快捷键

| 键 | 行为 | | 键 | 行为 |
|---|---|---|---|---|
| `P` | 演讲者模式 | | `X` | 清除标注 |
| `L` | 激光笔（红点短暂淡出，不保存） | | `B` / `W` | 观众屏黑屏 / 白屏 |
| `C` | 圈选（保留在当前页，翻页清除） | | `F` | 冻结 / 恢复观众屏 |
| `A` | 自动翻页 | | `R` | 开始 / 结束排练 |
| `?` | 快捷键说明 | | `B`（主界面） | **低功耗静态模式** |

- 标注坐标**归一化后**传给观众屏，不受两端尺寸差异影响
- 冻结时演讲者**可以继续翻页**，观众屏保留原页；恢复时立即追平
- 进入总览 / 正在圈选 / 打开设置 / 浏览器不可见 / 观众屏黑白屏或冻结 / 失去同步 → **自动翻页倒计暂停**，离开暂停后**从原剩余时间继续**，不重头计时
- 到尾页**停止**，不自动回首页

### 5.7 低功耗模式（必须保留）

右下角必须提示 `B 静态`。按下后切 `body.low-power`：**停掉 WebGL / ASCII canvas 的 RAF，取消正在运行的 Web Animations，把当前页内容直接 reveal 到静态最终态**。

这是**投屏现场的保险丝**——老旧笔记本 / 投影仪带不动 WebGL 时的救场键。**不许删。**

## 六 · 外部依赖与离线兜底

| 依赖 | 来源 | 断网/受限时 |
|---|---|---|
| **Motion One** | 先试 `./assets/motion.min.js`（本地）→ 失败回落 jsdelivr CDN → 都失败则把 `[data-anim]` 强制 `opacity:1` | **内容永远可读**，演示不依赖网络 |

> **交付给用户前提醒一句**：把这个 HTML 单独发给别人时，对方**也需要能访问 jsdelivr** 才有图标与动效兜底。要完全离线，把 `motion.min.js` 和图标一起打包进 `assets/`。

## 七 · 生成后验证

```bash
# 演讲备注与页面 ID 一致性（两族通用）
node <SKILL>/scripts/notes_validate.mjs index.html
node <SKILL>/scripts/notes_validate.mjs index.html --target-minutes 30

# 极简风版式与排版测量
node <SKILL>/scripts/deck_validate.mjs index.html
```

`notes_validate.mjs` 会拦截：缺失/重复页面 ID、备注与页面错位、必填字段或可选字段类型错误、完整时间计划超出 90% 预算，以及计时 / 排练 / 自动翻页 / 标注 / 演前检查 / 观众屏恢复控件缺失。

### 浏览器实测清单（至少走一遍）

按 `P` 进演讲者模式、允许浏览器打开观众窗口，实测：前后翻页（预览 iframe **不重载**）· 宫格选页并返回 · 首页/尾页 · 尾页预览"演示结束"态 · 尾页重新开始 · 观众窗关闭后显示"未连接" · 重新打开后恢复同步 · 退出后观众屏关闭或显示结束遮罩 · 备注保存 · 计时开始/暂停/重置 · 排练记录 · 自动翻页暂停/恢复 · 激光笔 · 圈选 · 清除 · 黑屏 · 白屏 · 冻结 · 设置面板 · 演前检查。

**至少在一组常用尺寸和一组小屏尺寸下检查**：当前页/下一页上下排列，两个 iframe 宽高比均为 `16:9`，且都没超出容器。

### 代码之外必须做的

**代码只能证明类名和结构存在，不能证明版式舒服。** 生成后必须打开逐页看：

1. 截图前**等入场动效稳定**（1–2 秒），别把动画中间态当成版式问题
2. 先看视觉：大标题字重、标题与内容间距、图片是否与正文对齐、图片/说明是否碰到翻页组件
3. 再看代码：版式与内容形状是否匹配，有没有把数据版式拿来讲概念
4. 页面别扭时，**先判断是版式选错、组件缺失、组件滥用，还是间距/安全区问题** —— 不要直接加 `margin` 硬救

## 八 · 能力边界（不要默认提供）

这个运行时**只依赖当前 HTML 和浏览器本地能力**，不需要账号或在线服务。**不要默认加入**：

- ❌ 实时字幕 / 语音转文字 / 外部语音模型
- ❌ AI 排练教练或给演讲者打分
- ❌ 扫码提问 / 在线投票 / 云端互动后台
- ❌ 手机遥控或需要服务端中继的跨设备控制

排练结果**只做数据汇总**，不生成"教练式"评判。

### 不适合网页 deck 的内容

- 大段表格数据、多图叠加（用原生 PPTX）
- 培训课件（信息密度不够）
- 需要多人协作编辑（这是静态 HTML）
