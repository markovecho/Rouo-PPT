# 故障与恢复

> 全产线通用的**停止 / 继续**规则 + 恢复矩阵。

---

## 零 · 总铁律

- **必需产物失败 → 阻塞下一道 gate。** 便利性界面（预览/UI）失败 → 回退到正式通道，**不阻塞路线**。
- **禁止静默降级**：绝不因为「下游命令也许能容忍缺文件」就跳过必需 gate，也绝不为推进流程而篡改已确认的执行值。该修就修、该停就停、该请用户重新决策就重新决策。

---

## 一 · 恢复矩阵（按失败点）

| 失败点 | 阻塞? | 自动恢复 | 需要用户? |
|---|---:|---|---|
| 预览/确认界面启动失败 | 否 | 回退到对话确认 | 否 |
| 已确认的值在简报里被缺失/改动 | 是 | 从保留的确认对象 + 更新的明确指令修复 | 仅当确实无法满足 |
| 设计锁改了已确认身份或漏锚点 | 是 | 从完成的简报重写受影响行 | 仅当简报不完整 |
| 执行时发现立约漏了某角色/细节 | 该页阻塞 | 修简报/锁片段 | 仅当确认意图变了 |
| 执行上下文是全新/续跑/被压缩 | 是（重建前） | 完整读简报再读锁；中途则重载触发输入与最新已完成页 | 否 |
| AI 生图失败 | 是（默认） | 试 A→B，再问「修复重试 / 手动生成 / 取消重规划」 | 默认由用户选 |
| 网络取图失败 | 否 | 调整查询/来源，仍不行标 `Needs-Manual` | 仅当必需且无替代 |
| 执行前仍有 Pending/Failed 的图像行 | 是 | 重跑所属路径 | 仅当规则要求新选择 |
| 用户中途替换/新增图片 | 否 | 重跑图像分析 | 否 |
| SVG 质检器报**错误** | 是 | **一次完整运行，修全部错误，一次整合修复，再一次验证重跑**——绝不在单个修复之间反复质检 | 否 |
| SVG 质检器报**警告** | 否 | 继续，不必强制改 | 否 |
| 启用了备注但缺 `notes/total.md` | 是 | 先补备注 | 否 |
| 拆分/后处理/导出失败 | 是 | 修源头产物后只重跑失败及其下游 | 仅当缺必需资产 |
| 导出成功但用户想改浏览器内容再导 | 否 | 改完重跑后处理 + 导出 | 否 |
| **量产线：PPTX 0KB** | 是 | 用 `DispatchEx` 起新实例重跑（**别 `taskkill`**，会误伤用户未保存文档） | 否 |
| **量产线：图片不显示** | 否 | `os.path.join(OUT, file)` 拼绝对路径重跑 | 否 |
| **量产线：Quit 报错** | 否 | try/except 包裹，忽略（正常退出信号） | 否 |
| **量产线：COM Dispatch 失败** | 是 | 检查 WPS/Office 安装与 ProgID；无 Office → 切手作线并明说 | 是（切换产线需告知） |
| **量产线：请求 MS 却报告「真实身份是 WPS」** | 否 | 身份实证拦截成功，不是故障。详见 `10-drive-engine.md §四 坑 1/2` | 否 |
| **量产线：`Slide.Export` 成功但文件不存在** | 否 | 传了相对路径。COM 只吃绝对路径（本项目两处踩到） | 否 |
| **量产线：质检报警但数据看着没错** | 否 | 先判断是数据错还是**规则错**——引擎早期把底座出血条与 14pt 注释误判为违规。规则错就修规则，别改数据迁就 | 否 |
| **量产线：要「看得见应用在写」的证据** | 否 | 用 `--shot-window`（FrameClass + PID 差分 + `PrintWindow`，遮挡/最小化也拿得到带标题栏的窗口照）。前台锁仍抢不到「浮到最前」，别承诺 | 否 |
| **量产线：`com-probe` 报「缺少 pywin32」** | 是 | 用了没装 pywin32 的解释器。改用托管 venv（`tools.py` 已自动挑），见 `19-environment.md §八` | 否 |

## 二 · 全局停止 / 继续规则

| 条件 | 动作 |
|---|---|
| 必需 gate 产物缺失 | 停在那道 gate，并**点名**它 |
| 未明确要求的可选阶段 | **不要**当作恢复手段去跑 |
| 便利界面/服务失败 | 回退对话，或直接不带该界面继续 |
| 派生产物过期 | 从它的**源头**重生成 |
| 必需手动产物缺失 | 暂停并点名确切产物 |
| 校验或导出失败 | 修**拥有故障的源头产物**，只重跑失败及受影响下游 |
| 已确认的选择无法兑现 | 保留已确认需求可见；在允许范围内重试；仍不行则停、请求新决策 |

**缺值处理**：某字段缺失时，**只**遵循其所属 schema 声明的必需性、推断过程或固定默认值。**禁止**把兜底按类比推广到空值、未启用的条件字段。

## 三 · 恢复起点

核心原则：**在拥有故障的那一步恢复，不要重头重规划**，除非源头确实变了。

| 最后良好状态 | 从哪里恢复 |
|---|---|
| 立约产物（简报+锁）都完成 | 进入执笔阶段当前页 |
| 图片已就位、SVG 未开始 | 执笔阶段 D1 |
| SVG 完成且质检通过，缺备注 | 补备注 |
| SVG 与备注都完成 | 后处理 → 导出 |
| 导出后用户又改了内容 | 重跑后处理 + 导出 |
| 量产线图表改了 | 只重跑 gen_charts.py + `com_drive.py drive`，deck_data 未变则不动 |

## 四 · 与 Gate 文件的对应

- gate 文件（`direction-choice.md` / `design-brief.md` / `design-lock.md` / `brand-kit.md` / `deck_data.json`）缺失 = **阻塞**，按总纲 §六处理
- 「用户说继续」授权的是**进入下一步**，不是跳过该步内部的 gate
- 修复纪律：**在拥有故障的最浅层修复**（`08-page-craft.md` §十）
