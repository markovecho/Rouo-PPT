# 方向门 · 三版实视觉的完整流程

> 铁律 2 的详细执行。**风格族已由风格门选定之后**，再出三版真实视觉，用户选定后才执行。

---

## 与风格门的分工（先读这段，别搞混）

完整顺序：**读需求 → 铁律 1 事实核验 → 风格门（铁律 6）→ 方向门（铁律 2）→ 动手**

| | 风格门 | 方向门（本文档） |
|---|---|---|
| 问什么 | **五族体系选一**：电子风 / 极简风 / 水彩风 / 编辑风 / 蓝图风 | 选定体系内的**哪一种诠释** |
| 选择粒度 | 体系级（字体族、色板、骨架、能力边界全变） | 诠释级（同一套字体与色板，不同的布局与侧重） |
| 载体 | 一份风格选项说明（含锚点参照与推荐理由） | **三版真实视觉** |
| 产出 | `direction-choice.md` 的风格段 | `direction-choice.md` 的方向段 |

**两者不能合并**，也不能用方向门的三版代替风格门：三版同属一个体系时，用户在选"同一个东西的三种做法"，而不是"我想要哪种东西"。

详细规格 → `20-style-gate.md`

## 为什么要有这道门

### 边界：能在体系内用文字说清的事，不要拿文字替代真实视觉

风格门敢问，是因为**五族是五个有明确锚点与参照作品的成熟体系**——"瑞士国际主义"指向 Vignelli 与 Helvetica，"电子杂志"指向 Monocle。用户听到的是**可辨认的东西**，不是形容词。

方向门不敢只问文字，是因为**体系内部的诠释没有公认名字**。绝不能让用户在「只有文字、没看到视觉」时选方案——用户没有依据。所以不抛文字单选题（「你要繁复还是克制？」），而是跑三套互补逻辑各产出一版真实视觉，一次性摆出来让用户选**看得见的东西**。

### 为什么指定风格也不豁免

实测案例：用户说「苹果宣传片风格」，AI 判定「已说清楚」跳过三方向直接执行自选方案——被用户抓现行。

**「Apple 风格」是一个语境不是一个设计。** 深空暗场、大白底衬线、产品色沉浸都是合法诠释，选哪个是**用户的权利**。风格词收窄的是解释空间，不转移选择权。

指定风格时的处理：三套逻辑照跑，但轮盘在**语境兼容的风格子集**里抽，参照案例和设计师也挑该语境内的。

### 给了品牌名呢

三版**全部基于 A3 取到的同一套品牌资产**做，差异在设计**诠释**。资产不是差异化维度——资产是共同基础。

## 三套逻辑

### 逻辑一 · 🎲 秒数轮盘（随机 · 20 选 1）

```bash
date +%S          # 取当前秒数
# 秒数 % 20 + 1   # 得 1-20
```

到 `04-style-armory.md` 取该号风格，**严格按该风格的视觉 DNA** 实现。

**作用**：用时间掷骰子，**强制打破模型「每次都偷选安全极简」的确定性偏好**。

⚠️ 抽到还原度 <70% 的风格时，标注「该部分用纯色块降级，不假装做出原版质感」。

### 逻辑二 · 🏆 现实参照（标杆迁移）

选 1 个**世界上和该需求最相关、且设计明确出色**（最好获奖：Awwwards / Apple Design Award / FWA）的真实案例作为参照。

**流程**：
1. 先 `WebSearch` **核实该案例真实存在**与其设计语言（凭记忆断言可能指向不存在的案例）
2. 拆解：配色 / 字体 / 布局 / 标志元素
3. 迁移到用户内容上

### 逻辑三 · 🧠 最佳设计师（顶级定制）

深呼吸一口，认真想：

> **假如预算没有上限，世界上最适合为「这个用户、这个内容」做设计的工作室/设计师是谁？**

候选：Pentagram / Collins / IDEO / 原研哉 / 某个品牌自己的设计团队……**按内容调性选，不要总选同一个**。启用该设计师的设计哲学从头设计。

## 执行规范（三版共用）

### 内容与骨架

- 用**用户真实内容**，不是占位文。三版同内容只换设计逻辑，方便横向对比
- **三版布局骨架必须互异**：导航 / 构图 / 内容区结构至少一项结构性不同
  - ⚠️ 不许两版共用同一骨架只换色换字体——**共用骨架会被一眼识破「换皮」**

### 可读性硬底线（任何风格温度都不豁免）

- 正文 ≥14px，标签/注释 ≥12px，正文对比度 ≥4.5:1
- 留白必须是**构图**（首屏有明确视觉锚点），不是内容缺席
- ⚠️ 盲测实锤：安静派做过头 = 「大片死白 + 微缩字号，第一眼像页面渲染坏了」，直接输给普通 baseline

### deck 场景（重要）

🎞️ **绝不写竖向平铺长页**。每页独立 `<section>`（统一尺寸），deck 骨架三版统一，只换视觉风格。

- 多页 deck 三版各出 **2 页代表页**（封面 + 一页核心数据页，兼作语法 showcase），选定方向后再批量其余页
- **单页内容绝不自带页码/进度标记**——页码由 deck 外壳统一承载（实测出过「02/03」+「6/16」双页码打架）
- 截图按单页（1920×1080）

### 存放与截图

- 存当前**项目目录**：`<project>/design-demos/[逻辑名].html`，禁止放临时目录
- 截图用系统 Chrome headless（命令见 `19-environment.md` §四）

### 产出自检（防偷懒，进展示前必查）

✅ 确认 `design-demos/` 下真有 **3 个 .html**。少于 3 个 = 没走完三套逻辑，**补齐再往下，不许只做一版交差**。

## 展示

三版全部完成后**一起展示三张截图**，每版标明：

1. 用了**哪套逻辑**（轮盘 / 参照 / 设计师）
2. **具体**哪个风格 / 参照案例 / 设计师
3. 一句话说**为什么**这么选

> 「A 版是轮盘风格」没有信息量；「A 版是轮盘 21→2 号：黑底巨型数字剧场，参照 Steve Jobs 2007 Keynote 与 Spotify Wrapped」才有效。

---

## ⛔ 展示后必须停轮

结束回合等用户选择。**不得自行选定继续执行**——包括无人值守会话。这是真正只有用户能做的决策，停轮不算阻塞。

用户可以：选一版深化 / **混合**（「轮盘版的配色 + 设计师版的布局」）/ 微调重跑 / 全部重来。

```markdown
| B | 现实参照 | <案例名>（已核实） | ... | ... |
| C | 最佳设计师 | <设计师名> | ... | ... |

## 三版的语言差异（不是换色换字）

| 维度 | A | B | C |
|---|---|---|---|
| 底色 / 强调色 | | | |
| 视觉母题的诠释 | | | |
| 版面结构 | | | |
| 数据表达哲学 | | | |

三版共用同一批真实资产，差异只在设计诠释。

## 用户选择

**✅ 已选定：<版本>**（<日期>）
- 用户选择原话：**「<原话>」**
- 最终方向：<描述>

### 选定版的语法要点（后续改动须遵守）

- 底色 / 墨色分级 / 强调色（**只用于什么，不用于什么**）
- 字体：正文用什么；数值/编号/微标签用什么
- 页眉 / 规线 / 内容区起始位置
- 每页有且只有一句结论，放哪里
```

## 唯一豁免（仅此三种）

1. 用户**本次会话明说**跳过
2. **已选定方向后的迭代**（同项目改稿、加页、换素材——方向已是用户选的，不重新过门）
3. **非设计的机械操作**（转格式、导出、截图、修 bug、纯文字改动）

豁免必须落档 `direction-choice.md`，记用户原话或迭代来源。

---

## 弱 runtime 串行降级

不支持并行子代理时改**串行**跑三套：

- 每套开跑前**只读设计输入**，**清空对上一套的记忆**
- 用三个不同锚点（轮盘号 / 参照案例 / 设计师名）**物理隔离趋同**

串行也**必须出三版**，不许偷懒并成一版。
