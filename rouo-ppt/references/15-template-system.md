# 模板体系 · 可复用资产的创建

> 从参考通道或直接从需求，造**一个可复用的模板工作区**。
> **边界**：本路线**永不**把内容填进 PPTX、永不给已有 PPTX/SVG 加 Master/Layout 结构、永不输出用户最终 deck。它产出一个独立工作区，回接到手作线立约阶段。

---

## 子流程派发（4 选 1）

| 子流程 | 何时选 | 产出 |
|---|---|---|
| **建品牌包** | 只复用**身份**：色、字、logo、语气 | 身份 spec，无页面清单 |
| **建风格包** | 复用**沟通方法 + 视觉方向** | 方法、页面角色词汇、视觉默认 |
| **建版式包** | 复用**品牌中立的结构骨架** | 画布、页面语法、槽位契约、SVG 页面清单 |
| **建整套包** | 复用**带品牌的结构系统** | 整合的身份/结构 + 页面清单 |

> 完整源 PPTX **不能决定 kind**——只按「值得复用的稳定规则」分类。选定后**绝不**重开选择、跑两个子流程、混 schema。

---

## 流程总览

```
参考包摄入与分析 → 基于事实的提案 → ⛔用户确认门 → 预检 + 子流程执行
→ 校验产出 → [评审 PPTX] → [注册索引] → 输出
```

> ⛔ 在用户确认提案前，不得写任何最终模板目录、模板 SVG 或设计简报。

---

## Step 1 · 参考包摄入与分析

| 类型 | 供给 | 策略 |
|---|---|---|
| `.pptx` | 导入工作区 | `standard` / `fidelity` / `mirror` |
| SVG 资产 | 归一 → 建中间表示 → 可读性检查 | `standard` / `fidelity` |
| 图片/视觉 | 多模态逐张读 | 仅 `standard` |
| 文本/文档/URL | 转 Markdown 分析 | 仅 `standard` |
| 什么都没有 | 在 Step 2–3 收集必需值 | 仅 `standard` |

**基础规范抽取**（有参考内容时强制）——抽源的**可观察运作规则**（不是通用设计建议）：

| 领域 | 从哪抽 |
|---|---|
| 画布/页面几何 | 幻灯片尺寸、viewBox → `[fact]` |
| 身份系统 | 主题色、字体、logo → 导入则 `[fact]`，视觉估计 `[suggested]` |
| 版式语法 | Master/Layout、页边距、栏、卡网格 → **模板专属规则** |
| 图像系统 | 裁切、scrim、满幅区、主视觉位 → 带源示例的放置规则 |
| 密度节奏 | 标题尺度、块数、密集 vs 呼吸 → 页型指引 |
| 页面清单语义 | 封面/目录/章节/内容/结尾变体与槽位 |
| 资产策略 | 模板拥有 vs 仅样例的图/图标/纹理 |

**来源标注**：`[fact]`（可独立追溯的权威/元数据）/ `[suggested]`（AI 推断）/ `[decision]`（用户明确写下）/ `[derived]`（内部执行值）。

> 「slide_07 用了左侧图片裁切」是**事实**；「案例页可用左侧图片栏」才是**可复用规则**。

## Step 2 · 基于事实的提案

用用户语言写**一份**自然语言提案，每个实质值标注来源。**只给一个推荐计划，绝不摆模式菜单。**

必答字段：输出范围（库 / 项目）、目标项目、子流程、方法方向、画布（确切像素 + viewBox）、创造计划、资产打包。

## Step 3 · ⛔ 用户确认门

用**一条**消息回显定稿提案，等用户明确回应。从文件或先前对话里**静默推断**值是**路线违规**——即便一个完整 PPTX 也只**告知**提案，不构成确认。

## Step 4 · 预检 + 子流程执行

- **预检（任何最终写之前）**：路径检查、库内目录为空、资产不覆盖既有文件——任一失败即中止且不写任何东西
- 版式/整套包分支：切到模板设计师，绑定工作区/提案/分析
- **强制**：策略为 `standard`/`fidelity` 时，选轮廓之前完整读 `08-page-craft.md` + `09-shape-language.md`
- **硬规则 —— 多 Master 边界**：多于一个 Master 仅在刻意保留源图或定义不同设计族时有效——**绝不一版式一 Master**
- **精灵图保留**：PPTX 导出资产常是嵌套 `<svg viewBox>` 裁切的精灵图；该嵌套是**承重几何**，**绝不**拍平成单个 `<image>`

## Step 5 · 校验

```bash
python "…/scripts/tools.py" check "<template_workspace>/templates" --template-mode --canonical-authoring --format <canvas_format>
```

**这是硬门**：未通过前不得有评审 PPTX、注册或交接。

## Step 6 · 评审 PPTX + 多 Master 门

仅版式/整套包：校验后清单声明**多于一个** Master 时必需。校验：文件存在且页数等于清单；每个 Master 指向不同 Theme 部件；编写模式每个载体绑定占位符匹配其 Layout 的类型/索引/画框。多 Master 失败**阻塞注册**。

## Step 7 · 注册到库索引（仅库范围）

库范围走注册器更新该 kind 的索引；项目范围跳过注册器，报告「未注册（项目工作区）」。

## Step 8 · 输出确认

汇报：模板名 / Kind / 输出范围 / 工作区路径 / 主色 / 索引注册状态 / 包含的文件清单。

**交接**：`<template_workspace>/` 根回接到手作线立约阶段——它作为指定候选出现，仅当它是唯一根时被预选。

---

## 关键规则速记

1. 品牌包/风格包**不写 SVG**；版式/整套包读 `08-page-craft.md`
2. 整套包 SVG 用简报配色；版式包不拥有身份色；风格包只拥有可覆盖默认
3. Theme/Master/Layout/Placeholder 是**编译后的 PowerPoint 对象**：版式包拥有拓扑与放置，品牌包拥有身份值，风格包拥有可移植方向
4. 占位符用 `{{}}` 与规范名
5. **禁止**把包修复编码进 SVG；不把原生结构或源 PPTX 打包为模板输入
