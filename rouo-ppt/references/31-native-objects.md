# 原生对象清单 · 可编辑性的完整外延

> 什么时候读：**铁律 3「原生可编辑」需要落地的时候**。
> 「文字和形状可编辑」只是及格线——表格、图表、公式、链接、图案填充各有各的原生形态。
> 凡是「用户可能想改」的东西，就不该以位图交付。
>
> 本文件按「原生 → 降级」给出每类对象的**判据、落地路径、能力边界**。

---

## 一 · 总原则：先问「用户会不会改它」

| 用户会改吗 | 交付形态 | 例子 |
|---|---|---|
| **会改** | **原生对象**（表格 / 图表 / 公式 / 链接 / 形状） | 数据表、柱状图、公式、跳转链接、结构框图 |
| 可能微调位置 | 原生形状 | 装饰线、色块、引线 |
| 不会改，只当背景 | 位图（可接受） | 照片、纹理、水彩晕染层 |
| 不会改，但**是内容** | 位图 + **保留源** | 复杂插画（把源文件留在项目里） |

**判断一句话**：这张图/这个块，用户半年后要改里面的**字或数**吗？要 → 原生；不要 → 位图。

---

## 二 · 原生表格

**判据**：出现 rows × columns 的事实（分数线、参数表、对照表、课程表）。

| 线 | 落地方式 |
|---|---|
| 手作线 | SVG `<table>` 语义 → 导出为原生表格；或直接走 `--native-charts-and-tables` 变体 |
| 量产线 | `deck_data.json` 的 `table` 元素类型（`com_drive.py` 内置逐格绘制，`WordWrap=False` 防换行） |
| 原生编辑 | 已有 PPTX 里的表格保持原生，只换单元格文本（`13-edit-existing.md`） |

**硬规则**：

- **单元格文字单行不折行**：字号不够就缩到下一档，不要让它换行（换行会把行高撑爆）
- 行高 ≥ 28pt，表头品牌色底 + 反白字，隔行交替着色
- 表格**不贴标题**：与标题间距 ≥ 24pt（同 `11-deck-data-format.md` 全局硬规则）

---

## 三 · 原生图表（可编辑数据）

**判据**：用户可能想换数据、改系列名、调坐标轴。

**两条路线，按需要选**：

| 路线 | 产物 | 何时选 |
|---|---|---|
| **图形路线**（默认） | matplotlib 透明底 PNG，或 SVG 派生形状 | 视觉自由度优先、只要好看 |
| **原生路线** | PowerPoint 原生 Chart 对象，右键可「编辑数据」 | 用户要改数、要复用为模板、要走审批 |

**原生路线的纪律**：视觉与数据是**两套真相**，必须明确谁为准。

- **视觉优先（默认）**：图形是权威，JSON 数据是它的投影。改图必须同步回数据，否则下次重建就丢
- **数据优先（模板/原生导入）**：内联 JSON 是权威，可见图形是它的近似预览。改数据要重新生成预览

> **不要两边都当真相。** 一边改一半，最后没人知道哪个对——这是「改完图数据不一致」的唯一成因。

**量产线的选择**：`com_drive.py` 走的是**图形路线**（matplotlib 透明底，`10-drive-engine.md` §工步 2），
因为它追求跨引擎稳定与视觉自由。需要「编辑数据」时，在收尾时用原生路线**单独存一份**，两份都给用户。

---

## 四 · 原生公式（LaTeX → Office Math）

**判据**：页面出现**结构性数学**——分式、根式、积分、求和、极限、矩阵、括号构造、上下标复合。

> 短变量、百分比、简单赋值（`O(n log n)` 这种）、`x = 5` 这类 **当普通文字**即可，不要为它上公式对象。

**用 `scripts/omml_math.py`**（本机已实测跑通全链路）：

```bash
# 环境自检：依赖 + 转换表
<venv>/Scripts/python.exe scripts/omml_math.py check

# 库用法（写进你的 python-pptx 项目）
from omml_math import append_math
append_math(text_frame, r"E = mc^{2} + \\frac{a}{b}", size_pt=32)      # 块级公式，新起一段
append_math(text_frame, r"O(n\\log n)", size_pt=20, inline=True)       # 行内，接在本段尾

# 目视验证：生成含公式的样例 pptx
<venv>/Scripts/python.exe scripts/omml_math.py demo exports/_math_demo.pptx
```

**链路**：`LaTeX --latex2mathml--> MathML --MML2OMML.XSL--> OMML --注入 a14:m --> pptx`

- 转换表用**本机 Office 自带**（`C:\Program Files\Microsoft Office\root\Office16\MML2OMML.XSL`），或用 `ROUO_MML2OMML_XSL` 环境变量指到 LibreOffice 的 `math.xsl`
- 依赖装法（PyPI 直连不稳，走镜像）：
  `<venv>\Scripts\python.exe -m pip install latex2mathml -i https://pypi.tuna.tsinghua.edu.cn/simple`

**实测结论（本机 WPS 12.1 回导验证）**：

| 结论 | 说明 |
|---|---|
| ✔ 可编辑 | 生成的是 OMML，双击进入公式编辑器，**不是图片** |
| ✔ 渲染正确 | 分式、根式、积分上下限、求和上下限、上标全部正常排版 |
| ✔ 打开无修复提示 | WPS 直接打开，不触发文件修复 |
| ⚠️ 字号 | 由 `a:pPr/a:defRPr@sz` + 每个 `m:r` 的 `w:rPr@sz` 双写；只写一处在某些引擎下不生效 |
| ⚠️ 行内追加 | `inline=True` 追加到**当前最后一段尾部**——所以先写正文、再追加行内公式 |
| ❌ 不支持的 LaTeX | 宏包命令（`\begin{align}` 环境、自定义宏）不被 `latex2mathml` 识别，会原样输出 |

**降级**：链路不可用时，用**矢量绘制**公式（手作线的形状语言），并在备注里保留 LaTeX 源，同时明说降级。

## 五 · 原生超链接

**判据**：用户指令、事实来源或页面计划里要求「可点击跳转」——外链，或跳本 deck 的某页。

| 意图 | 形态 |
|---|---|
| 整对象 / 图 / 按钮 / 成组 | 给整组加链接（点哪儿都跳） |
| 行内文字 | 只给那一段文字加链接 |
| 同 deck 跳转 | 指向目标页（按**最终**页序的序号） |

**硬规则**：

- **不许猜目标**。链接地址缺失或模糊 → 回到上游问清楚，**绝不**用搜索结果或猜的 URL 顶替
- 同 deck 跳转按**最终**页序算——中途插删页后必须重算一遍
- 链接是内容，**不是**确认项/资源清单/`design-lock` 条目——别把它塞进资源表

**线间差异**：

- 手作线：SVG 里 `<a href="...">` 包裹对象或行内文字，导出时保留为原生关系
- 量产线：`com_drive.py` 目前**不**内建超链接路由；需要时在收尾用 python-pptx 补 `click_action.hyperlink`（同一页元素定位见 `11-deck-data-format.md`）
- 网页线：就是 `<a href>`，但注意演讲者模式下别让链接抢翻页键（`25-web-deck.md` §三）

## 六 · 原生图案填充（预设枚举）

装饰性填充用 **DrawingML 预设图案**，不要贴纹理贴图——预设图案矢量、可换色、体积为零。

写 `data-pptx-pattern`（或对应 API 的枚举名），**只能取下列闭集**，乱写会让 PowerPoint 报「需要修复」：

| 类别 | 取值 |
|---|---|
| 网格 | `smGrid` · `lgGrid` · `dotGrid` |
| 斜线 | `ltUpDiag` · `ltDnDiag` · `dkUpDiag` · `dkDnDiag` · `wdUpDiag` · `wdDnDiag` · `dashUpDiag` · `dashDnDiag` · `diagCross` |
| 横竖线 | `horz` · `vert` · `ltHorz` · `ltVert` · `dkHorz` · `dkVert` · `narHorz` · `narVert` · `dashHorz` · `dashVert` · `cross` |
| 百分比网点 | `pct5` · `pct10` · `pct20` · `pct25` · `pct30` · `pct40` · `pct50` · `pct60` · `pct70` · `pct75` · `pct80` · `pct90` |
| 格纹 & 彩点 | `smCheck` · `lgCheck` · `smConfetti` · `lgConfetti` |
| 装饰 | `horzBrick` · `diagBrick` · `weave` · `plaid` · `trellis` · `zigZag` · `wave` · `sphere` · `divot` · `shingle` · `solidDmnd` · `openDmnd` · `dotDmnd` |

**缺省与错误**：未标注 → 回退 `ltUpDiag` 并给一条保真警告；**写了非法名 → 报错**（不是警告，因为文件会打不开）。

配色：前景/背景色各自取一个（背景默认白），或取图案子元素的第一笔填充。**不要**用图案变换矩阵。

**风格适配**：蓝图风常用 `dotGrid` / `smGrid`（网格底）；编辑风常用 `pct10`–`pct30`（网点/半调）；水彩风**不用**（它要的是颜料渗化，不是规则纹理）。

## 七 · 原生形状与连接符

形状与几何技法在 `09-shape-language.md`（预设形状词表 + 布尔决策门 + 纯几何建模）。
这里只补一条**易错点**：

- **连接符（连接线）必须真正连接端点**，而不是「画一条线摆上去」。摆上去的线在用户拖动形状时会脱开
- 流程图里每一段的首尾要**对位闭合**：上一段的出口 = 下一段的入口；该留空隙的地方（语义断开）才留空隙
- 拓扑装配先解决**相对关系**（共享基准/中心/锥度、端点对齐、接触或有意留白、嵌套边距、重叠深度），
  再落坐标。**不要**照抄某个版式的坐标——坐标是结果，不是输入

## 八 · 能力边界（哪些做不到，怎么降级）

| 需求 | 能做到吗 | 降级方案 |
|---|---|---|
| 原生 Chart + 可编辑数据 | ✅ 单独存一份原生版 | 平时走图形路线，收尾补一份 |
| 原生公式 | ✅ 已实测 | 矢量绘制 + 备注留 LaTeX 源 |
| 原生超链接 | ✅ 手作线/网页线原生；量产线需收尾补 | 在页面角落写明完整 URL |
| 图案填充 | ✅ 预设闭集 | 换成低饱和纯色块 |
| 动画/切换效果 | ✅ 走 COM `AddEffect`（`16-motion-voice.md`） | 网页线交付，动效更可控 |
| SmartArt | ⚠️ 可保留已有，**不新建** | 用原生形状手工搭（质量更好也更好改） |
| 复杂 LaTeX 环境 | ❌ | 拆成多行独立公式，或矢量绘制 |
| 图表内的自定义图例/标注 | ⚠️ 部分 | 图表留白处补原生文本框做标注 |

## 九 · 交付前怎么确认「真的可编辑」

别只看导出的 PNG——**要打开源文件点一点**：

- [ ] 表格：双击单元格能进编辑态，文字是文本不是图形
- [ ] 图表：右键有「编辑数据」（走了原生路线时）
- [ ] 公式：双击进公式编辑器，能改符号
- [ ] 链接：能点开/跳转，地址正确
- [ ] 文字：随便挑 3 处双击，都能改（这是铁律 3 的最低验收）
- [ ] 文件打开**无**「需要修复」提示

量化的部分交给 `29-preflight-checklist.md`；这里只做「可编辑性」的抽样实测。
