# 预检与后验测量清单 · 交付前的双面校验

> 什么时候读：**任何产出视觉的任务**——网页线每一页、手作线每一页、量产线每一页。
> 这份清单分两半：**生成前**防错（省返工），**生成后**测量（省肉眼）。
>
> 为什么必须有：AI 写的版式**肉眼看着没事，量出来已经越界**；而越界这件事一旦靠肉眼判，
> 就会变成「改一处引入两处」。所以——**先量，再改**。

---

## 第一部分 · 生成前预检（Pre-flight）

**按顺序做，任何一步没过就不要往下写内容。**

| # | 动作 | 判据 |
|---|---|---|
| P1 | **占位符清零** | 骨架里的 `[必填]` 全部替换。拷完第一件事就是 `grep -n "\[必填\]" index.html`，输出必须为空 |
| P2 | **类名白名单** | 页面里出现的**每一个结构类名**都来自骨架 `<style>` 里的定义。凭印象新造的类名 = 静默失效（不报错，只是没样式） |
| P3 | **主题色整体替换** | 只替换标了「主题色」的 `:root` 变量块，**不要逐处手改**散落的 `var()` 引用 |
| P4 | **主题节奏规划** | 全篇不要一片同调。亮/暗页交替（例：亮-亮-暗-亮-暗-暗-亮），并在页面计划表里**事先写死** |
| P5 | **字号双约束** | 大字号取 `min(Xvw, Yvh)`，且 **Y ≥ X × 1.6**。只锁 vw 会在矮屏溢出，只锁 vh 会在宽屏过小 |
| P6 | **图片槽位先定** | 先定比例与落位，再去取图/生图（`28-image-prompts.md`、`26-shot-framing.md`） |
| P7 | **chrome 与 kicker 不重复** | 页眉/角标与页内小标题写同一句话 = 冗余，改掉一方 |
| P8 | **正文语言与字体分工** | 标题衬线、正文非衬线（或各族自己的分工，见风格文档）；图内文字语言 = deck 语言 |

> **P2 是最常被跳过、代价最大的一条**：类名错了页面不报错，只是「长得不对」，
> 而人会先去怀疑「是不是审美问题」，白改半天。

## 第二部分 · 画布对齐法则（每生成一页都先过）

这条在极简风最容易踩（它的骨架把对齐写得很硬），但**所有风格都成立**：

1. **一条左基准线**：同页所有正文左边缘对齐到同一条 x；不要「这段缩进 8px 那段缩进 12px」
2. **一条顶基准线**：kicker / 大标题 / 正文的层级靠**字号与间距**表达，不靠各自乱飘的 y
3. **元素不得同时贴两个边**：贴左就让它右松，贴顶就让它下松；四周都贴 = 窒息
4. **底部安全区**：最低处元素不要碰到翻页控件/导航条；竖版还要避开平台 UI（`32-canvas-formats.md`）

**违反任一条 = 整页重排，不要局部挪**——局部挪必然把越界从一处搬到另一处。

## 第三部分 · 生成后：先测量，再改版式

### 3.1 后验测量法（顺序不能反）

```bash
# 网页线：量「超出」与「空白」，不改内容
node scripts/deck_validate.mjs index.html
```

测量输出的是**每个越界量是多少 px**。正确反应顺序：

1. **先看是不是测量本身错了**（量测区避开了装饰层吗？元素是真的越界还是被误判？）
2. 再按**溢出量分档**修版式（下表）——**绝不靠删内容来消越界**
3. 改完**重新量一次**，确认没有把越界搬到别处

| 溢出量 | 修法 |
|---|---|
| ≤ 40px | 只压本地间距/内边距（20–40px 以内），**不动内容** |
| 41–90px | 压缩局部 gap / padding，减一个块的固定高度；尽量不删文案 |
| 91–160px | 微调 display 标题字号，或压缩一个段落；仍先于删内容 |
| > 160px | 换容量更大的版式，或与用户确认后**有意**删/并内容 |

> **「只有 Npx」的心态是对的**：越界 20px 是间距问题，不是内容问题。
> 把它当内容问题处理，会顺手删掉本来该留的字。

### 3.2 深色/浅色主题回归检查

换主题后**必须**重看一眼：

- 亮色页面配了暗色动态背景 → 整体发灰（主题切换没生效）
- 整个 deck 全是同一种明度 → 没有节奏（回到 P4）
- 角标/页眉颜色没跟着主题走 → 在暗底上直接看不清

## 第四部分 · 硬规则清单（每条都必须修掉）

**逐项过，命中即改。** 固定区（画布外）问题优先，其次叠层顺序，最后可读性。

| # | 类别 | 触发条件 | 允许的修法 |
|---|---|---|---|
| H1 | **越界** | 元素包围盒超出画布 | 缩小或移回画布内 |
| H2 | **文字溢出** | 文字包围盒超出它的视觉容器 | 减字号或换行（**不删字**） |
| H3 | **文字重叠** | 两个文字包围盒相交（同一段内的行内单元除外） | 挪位或改尺寸 |
| H4 | **可读性不足** | 对比度 < 4.5（小字）/ < 3.0（字号 ≥ 24px），或文字直接压在复杂图上且无蒙层 | 加蒙层 `<rect>`，或把文字提到 ≥ 24px 走 3.0 阈值；**品牌色 token 不许改色**，只许加蒙层 |
| H5 | **元素碰撞** | 矩形/圆/路径包围盒重叠且叠层顺序违反语义 | 打开间距 |
| H6 | **已声明 chrome 位移** | 页面计划或模板明确声明的页码/页眉/页脚被遮挡、丢失或出画布 | **只恢复那一处**；**绝不补造**计划外的 chrome |
| H7 | **图片渲染异常** | `<image>` 空/坏/严重变形 | 修路径；`cover` 太狠就改 `fit-contain`；需要重新裁切就回到图片规范 |
| H8 | **字体回退** | 用了本机没有的字形（稀有 Unicode、特殊符号）→ 渲染成豆腐块 | 换通用字形或改图形绘制（见 `30-motion-recipes.md` §五） |

**H4 的阈值记牢**：**4.5:1（普通文字）/ 3.0:1（≥24px 大字）**。这是硬线，不是建议值。

## 第五部分 · P0 / P1 分档

把上面各组按「不改就不能交付」和「改了更好」分两档，避免在小问题上耗尽预算。

### 🔴 P0 —— 不改就不能交付

- 画布对齐法则违反（第二部分）
- 硬规则 H1–H4 命中
- 占位符残留（P1）、类名不在白名单（P2）
- 备注与页面 ID 不对应（网页线正式演讲场景）
- 图片被裁掉了关键信息（左右/顶部被切，只剩底部裁切是允许的）
- 用 emoji 当图标

### 🟡 P1 —— 改了明显更好

- 排版节奏：全篇同一个明度、间距到处不一致
- 大标题过长导致折行难看
- 图片比例不统一（同组混用高度）
- 角标与页内小标题语义重复
- 图注（caption）缺失或断句奇怪

**P0 全清 + P1 大部分清** = 可以交付。P1 未清要在收尾里**说明**，不要假装没有。

## 第六部分 · 视觉 + 代码双核对

**只看渲染图会漏结构问题；只看代码会漏视觉问题。两个都要看。**

| 看什么 | 怎么看 | 抓什么 |
|---|---|---|
| **视觉** | 逐页截图（`19-environment.md` §四 Chrome headless），与设计基准并排比 | 越界的视觉表现、对比度、比例不统一、留白失衡 |
| **代码** | 读渲染后的文本结构（类名、层级、层级顺序） | 类名失效、叠层顺序错、chrome 缺失、重复 id |
| **双维交叉** | 把两边发现对一遍 | 知道「哪里不对」也要知道「为什么不对」——只改一个维度必然反复 |

**实测结论：跳过「代码」这一维，会在「视觉看着怪但说不出哪怪」上反复改 3 轮以上。**
